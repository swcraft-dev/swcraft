# SWCraft 0.4.0

**This is the release that puts working with the model into the editor.** It carries JSON
Schemas for every YAML layer and the manifest, derived from the model contract, and the
extension pack, the reworked SWCraft panel, readable diagrams, the walkthrough and
the editor-tooling health check. Nothing in the YAML model, the editing protocol, the 13-tool MCP
surface or the emitted ARXML bytes changes; everything below is about the editor and the two small
CLI/generator surfaces that serve it.

Upgrade all four artifacts together, as always:

```
swcraft-tools==0.4.0
swcraft-mcp==0.4.0
swcraft-agent==0.4.0
```

plus `swcraft-vscode-0.4.0.vsix`. Read **"Three changes an existing project can notice"** below
before upgrading; the first one can keep the extension from installing at all.

---

## Editing YAML with the model's own knowledge

Installing the extension now brings completion, hover and diagnostics to every model file and to
`swcraft.yaml`:

- Eleven JSON Schemas, one per layer plus the manifest, are generated **from the model contract**
  (contract `1.4.1` — every kind and field now carries a description written for a reader, not a
  maintainer) and shipped inside the VSIX. A drift gate regenerates them at build time, so the
  schemas cannot lag the contract.
- Completion offers the declared fields and enum members and inserts defaults (`type: application`,
  `core: 0`); hover shows the field's description and its unit (`(unit: bytes)`, `(unit: s)`);
  a mistyped key, a wrong type, an invalid enum member and a missing required field are each
  underlined with the property named.
- The association is by layer directory (`**/tasks/*.yaml`, `**/swc/**/*.yaml`, …), so it follows
  a custom `model_root` unchanged — and it takes precedence over the public SchemaStore catalog,
  which used to claim `model/tasks/*.yaml` as *Ansible* files and cover them with foreign errors.
- What the schemas deliberately do not check (the AUTOSAR identifier rule, cross-layer references,
  budgets) is documented per file: the editor helps, **`SWCraft: Validate` is the gate**.

## One install, the whole toolset

- The extension is now an **extension pack**: installing `swcraft-vscode-0.4.0.vsix` on a host
  with gallery access also installs Red Hat YAML, LikeC4 and Red Hat XML. `.arxml` files open as
  XML with outline, breadcrumbs and well-formedness diagnostics; a scaffolded
  `.vscode/settings.json` turns off LemMinX's schema check for `*.arxml` (it cannot see the
  licensed AUTOSAR schema and would mark correct files red) while keeping well-formedness.
- The SWCraft panel is reorganised into **Model** (Validate, Generate C4, Open Generated C4,
  Diff, Impact, Resource Report, Export Component) and **Setup** (Onboard, Repair/Open MCP
  Config, Check Editor Tooling). Every item shows a verb-and-time status (`validated 14:02`) that
  clears itself. Export Component and Impact open a QuickPick over the model's elements instead
  of asking for a typed name.
- `swcraft list [LAYER] --project PATH [--format text|json]` is the one new CLI surface: a
  read-only listing of every declared layer's elements, in contract order; the QuickPicks are
  built on it.
- `generate c4` now emits **explicit static views** — `index` (Model overview), `components`,
  `tasks`, and one `group_<group>` per SWC group — so LikeC4 no longer improvises a single
  unreadable landscape; every `dynamic view` carries `variant sequence` and opens as a sequence
  diagram with lifelines.
- **`SWCraft: Check Editor Tooling`** reports the pack members with versions, the CLI interpreter
  and the bundled schemas — and states, in the report itself, what it cannot see. A missing or
  disabled member, or a missing interpreter, is a named `[problem]` with the action to take,
  never a bare `spawn ENOENT`.
- A six-step **walkthrough, "The first hour with SWCraft"**, covers the panel, onboarding,
  editing with schema help, Validate, the diagrams and the Copilot agent; steps complete from the
  real actions.
- In an **untrusted (Restricted Mode) window** the SWCraft view and commands are deliberately
  absent — the extension declares why, and the reason is shown on its extension page: every
  SWCraft command spawns the workspace's own interpreter. Trust the folder to get them back.

## Three changes an existing project can notice

1. **The extension's VS Code floor is now `^1.110.0`** (was `^1.90.0`; the floor is LikeC4's).
   A VS Code below 1.110.0 cannot install the extension at all — the failure happens at install
   time, so no SWCraft surface runs to explain it.
2. **Four view names are reserved: `index`, `components`, `tasks`, `group_<group>`.** LikeC4
   keeps static and dynamic views in one namespace, so a `Sequence` named `components` — legal
   before, and still legal to `check-model` — now makes `swcraft generate c4` exit 1 with a
   message naming both claimants. Rename the sequence.
3. **Two SWC group directories that differ only in a character outside `[A-Za-z0-9_]` now
   collide** (`swc/brake-ecu/` beside `swc/brake_ecu/` both become `group_brake_ecu`); the
   generator refuses, naming both. A single such directory is fine.

## Upgrade checklist

1. Install the four artifacts at `0.4.0` (VS Code ≥ 1.110.0).
2. Re-run `SWCraft: Onboard Project` (or `Repair MCP Config`) once: it scaffolds the new
   `.vscode/settings.json` (the `.arxml` filter) and refreshes the `.github/` assets.
3. If a sequence is named `index`, `components`, `tasks` or like a group view — rename it.
4. Nothing else: model, manifest, MCP configuration and generated ARXML are unchanged.
