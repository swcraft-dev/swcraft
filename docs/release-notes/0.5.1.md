# SWCraft 0.5.1

A one-command patch release from `release/0.5`, for the demonstration track. The model contract,
the editing protocol, the MCP tool surface and the emitted ARXML bytes are unchanged from 0.5.0;
a 0.5.x project upgrades by installing the four artifacts.

```
swcraft-tools==0.5.1
swcraft-mcp==0.5.1
swcraft-agent==0.5.1
```

plus `swcraft-vscode-0.5.1.vsix`.

## `SWCraft: Check Model` in the panel

The extension's *Model* section gains a twelfth command, directly under `Validate`:
`swcraft check-model` — the same model checks, with nothing written and no ARXML generated.

It exists because of a measurement, not a preference. On the Windows host of the demonstration
track, with a licensed AUTOSAR schema configured and a five-component model: `validate` 5.56 s,
`check-model` 1.59 s. The difference is not ARXML generation — on a Linux host with the same
model and no schema configured, `validate` (model checks *and* generation) takes 0.5 s in total.
It is **compiling** the AUTOSAR XSD, which happens on every click because `arxml_validation.py`'s
compiled-schema cache is per-process and the panel spawns a fresh CLI each time. Splitting ARXML
generation out of `Validate` would therefore have bought nothing — the cost stays on the
validation side. Skipping the XSD entirely is what makes the fast check fast.

What it does not remove: `check-model`'s own 1.59 s on that host is process start-up (the same
command measures ~0.5 s on Linux), and the two figures come from two different machines, so
neither is a benchmark of the other. The measurement is recorded in the showcase repository's
Windows run evidence.

**What this does not change:** `swcraft validate` is still the sole authoritative model and
ARXML/XSD gate. `Check Model` writes nothing, generates nothing and validates no ARXML, so a
green `Check Model` is not evidence about the generated artifact and may never be cited as
qualification evidence — the same rule the extension pack's format-responsibility contract
already states for every editor-side diagnostic. It is the edit loop; the gate is unchanged.

The command is also in the Command Palette as `SWCraft: Check Model`, and it resolves the CLI
the same way every other CLI-spawning command does: the project's own `.venv` first, the
proto-managed shim only as a fallback.

## Upgrading

Install the four artifacts and reload VS Code. Nothing in a project changes: no manifest key, no
model file, no generated output. A project that keeps its own pinned
`requirements-swcraft.txt` raises the three `==` pins.
