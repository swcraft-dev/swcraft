# SWCraft 0.19.1

Released 2026-10-23. A patch release of the 0.19 line: three answers that grew with the model are now
bounded by the question. `impact_of`'s default summary answers its first twenty rows, the assistant
profile asks for one component's unconnected ports in one read, and `find` answers at most sixteen
candidates in all. In 0.19.0 each of these answers grew with the model, up to a refusal on a
large one; now each is bounded by the request. The MCP server still has twelve tools,
and the ARXML SWCraft generates and the model's format are unchanged from 0.19.0. *What upgrading
takes* at the end has one step beyond the pin: copying the new assistant profile.

## `impact_of`'s summary answers its first page

A `summary`, the default form, sent with no `limit` over a walk of more than twenty rows now
answers the walk's **first twenty rows**, at the requested depth. Its footer is the one a page
already printed: the page, the walk's total, the count of each kind in all, and the `after` cursor
for the next page. A walk of twenty rows or fewer is answered exactly as in 0.19.0. `full` still
answers the whole walk and is refused when it is over the answer budget; `count` is unchanged.

A refused answer now names the next request in a chain of three steps: a refused `full` is offered
the summary, and a refused summary is offered `depth=1`, then the count. The step that offered a
page of fifty is gone, since the summary is paged already.

The default summary of a much-used interface or of a large component therefore no longer grows
with the model, and its footer still counts the whole walk.

## One component's unconnected ports in one read

The profile has a new recipe, *A component's unconnected ports*: the member read of the ports with
`unconnected`, joined on `element` to that one component's row of the `swc` layer, so only its own
ports answer. It asks for the count first, then the first twenty with `limit: 20`. The read answered
this in 0.19.0 already; what was missing was the recipe, so the agent read every component's ports.
*Ports that nothing connects* now also counts first and then asks for a page of twenty. On a long
list the answer is the number, the first twenty and the note that the rest come by `after`.

A component's count and its page of twenty stay small on any model, and so does the whole layer's
page of twenty, where the whole layer with no `limit` grows with the model. The join with
no `limit` is still large: the recipe's `limit: 20` is what keeps the answer small.

## `find` is bounded by the request

`find` still resolves up to sixteen names in one call, and now answers at most **sixteen candidates
in all**: five a name for up to three names, fewer above (four names answer four each, sixteen names
one each). Each name's candidates are its first ones in the same order as before, and `more` still
counts the rest per name. Sixteen names now answer at most sixteen candidates, where they could
answer eighty.

## The model's contract

`contractVersion` stays `12.0.0`. No model file needs an edit.

## The archive

The runtime payloads are 0.19.0's, unchanged: Node.js 22.23.2, CPython 3.11.16 (the
python-build-standalone build of 2026-09-01), `elkjs` 0.12.0 inside the `swcraft-tools` package, and
the two extensions of the pack, Red Hat XML 0.29.3 and Red Hat YAML 2.0.0, which is still the
Marketplace's newest release. The archive carries the same packages as 0.19.0. The Linux archive measures
**198 000 227 bytes** (SHA-256 `c3357402…e7db1fc6`) and the Windows archive **202 059 334 bytes**
(`3e31ae69…e01320bd`), as the tag run of 2026-10-23/24 published them: 4 703 and 13 693 bytes more
than 0.19.0's.

## What upgrading takes

1. **Install the 0.19.1 archive, then set `toolchain_version: "0.19.1"`** in each project's
   `swcraft.yaml`. Until you do, every command that writes or gates refuses a project pinned to
   0.19.0 with the pin sentence. The read-only commands (`diff`, `impact`, `list`, `query`,
   `resource-report`) and `swcraft guard` only print a warning, so Copilot keeps working meanwhile.

2. **Run *SWCraft: Onboard Project* again** to copy the new assistant profile, with its new recipe
   and the bounds of `find` and `impact_of`. Onboarding overwrites the profile, the Copilot
   instructions and the model guard, so keep a copy of anything you edited in them. An old profile
   keeps working; it only lacks the one-component recipe.

3. **A client of your own that reads these answers** meets two changes:
   - an `impact_of` `summary` with no `limit` over a walk of more than twenty rows now gets a page and
     its `next` cursor, not the whole walk; ask `form: "full"` for the whole walk. A refused summary
     is offered `depth=1` and then the count, no longer a page of fifty;
   - `find` with more than three names answers fewer candidates per name, sixteen in all.

The model's files, the hook file `.github/hooks/swcraft.json` and the generated ARXML are unchanged
from 0.19.0. A project on 0.18.x or earlier follows [0.19.0's note](0.19.0.md) first.
