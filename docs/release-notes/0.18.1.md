# SWCraft 0.18.1

Released 2026-10-21. A patch release of the 0.18 line: in VS Code, a report's preview shows the
latest run every time; the Change Report writes a second Markdown file for a pull request, without
the pictures; and its verdict line says how many findings the model already had. The set of MCP
tools and their arguments, the ARXML SWCraft generates and the model's format are unchanged from
0.18.0. The archive's sizes are recorded under *The archive*.

## The report preview shows the latest run

*Change Report* and *Experiments → Allocation (CARMA)* open their report in VS Code's Markdown
preview. In 0.18.0 a preview closed and opened again after a second run could still show the first
run's text, although the file itself was current: the Markdown preview kept its first rendering. The
preview is now redrawn each time a run opens it.

## A pull request file and the pipeline templates

`swcraft change-report` writes `change-report-pr.md` beside `change-report.md`: the same report
without its *Diagrams* section — no picture link, no legend, no "not drawn" note. The pictures are
build outputs that no repository holds, so a pull request comment names none of them. Each run
replaces the file like the others. The `Generated report:` line still names `change-report.md`
(the file VS Code previews), and `change-report.json` and `--no-diagrams` are unchanged.

The GitHub Actions and GitLab CI templates on the guide's *Change Report* page now
post `change-report-pr.md` and no longer pass `--no-diagrams`: the whole folder, the full report
with its pictures, stays the job's artifact (drawing needs Node.js, which the installation brings).
The page adds one line for Azure DevOps: post the same file as a pull request thread comment through
its REST API.

## The verdict counts the findings already in the model

The verdict line counted only the findings a change **introduces**, so `0 warning(s) introduced`
could read as a model without warnings while `check-model` showed 32. It now adds, in brackets, the
findings the model holds after the change that it already had before:

```text
**0 error(s) · 0 warning(s) introduced (32 already in the model) · 6 change(s) in 6 element(s) · 1 composition(s).**
```

Only the kinds that are not zero are named: `(32 already in the model)` when they are all warnings,
`(1 error, 32 warnings already in the model)` when both, nothing when there are none. The line is the
same in `change-report-pr.md`, and `change-report.json`'s `verdict` gains `existingErrors` and
`existingWarnings`; its `schemaVersion` stays 1.

## The archive

The runtime payloads are 0.18.0's, unchanged: Node.js 22.23.2, CPython 3.11.16 (the
python-build-standalone build of 2026-09-01), `elkjs` 0.12.0 inside the `swcraft-tools` package, and
the two extensions of the pack, Red Hat XML 0.29.3 and Red Hat YAML 2.0.0. The archive carries the
same packages as 0.18.0. The Linux archive measures **197 839 421 bytes** (SHA-256
`27ecf1bd…c255e0ca`) and the Windows archive **201 901 361 bytes** (`61778097…5968820b`), as the
tag run of 2026-10-21 published them: 10 645 bytes more than 0.18.0's on each.

## What upgrading takes

Install the 0.18.1 archive, then set `toolchain_version: "0.18.1"` in each project's `swcraft.yaml`.
Until you do, every command that writes or gates refuses a project pinned to 0.18.0 with the pin
sentence and never reaches the model. The read-only commands (`diff`, `impact`, `list`, `query`,
`resource-report`) and `swcraft guard` only print a warning, so Copilot keeps working meanwhile.

Nothing else in a project moves: the model, its format, the hook file `.github/hooks/swcraft.json`
and the agent files are the same as 0.18.0's. A pipeline built from 0.18.0's template keeps working;
to drop the pictures from its comment, post `change-report-pr.md` instead of `change-report.md`. A
0.17.x project upgrading straight to 0.18.1 follows [0.18.0's note](0.18.0.md) first.
