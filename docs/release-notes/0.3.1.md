# SWCraft 0.3.1

The first patch release from `release/0.3`, made for the showcase demonstrations. Three fixes, all found in
the first VS Code + Copilot rehearsal on 2026-08-23 and all inside the release-branch criterion:
the model contract, the editing protocol, the MCP tool surface and the emitted ARXML bytes are
unchanged from 0.3.0. A 0.3.0 project upgrades by installing the four artifacts; nothing else.

```
swcraft-tools==0.3.1
swcraft-mcp==0.3.1
swcraft-agent==0.3.1
```

plus `swcraft-vscode-0.3.1.vsix`.

## `swcraft validate` no longer prints xmlschema's content-model warning

With a licensed AUTOSAR schema configured, every XSD-mode run printed

```
…/arxml_validation.py:409: XMLSchemaWarning: can't verify the content model of {!r} due to exceeding of maximum recursion depth
```

above `Validation passed`. The warning is `xmlschema`'s own Unique Particle Attribution check
giving up on a handful of AUTOSAR content models; it says nothing about the document, changes no
verdict, and `SWCRAFT_XML_SCHEMA_RECURSION_LIMIT` does not reach it. It is now filtered — exactly
that message, only while the schema compiles. Any other schema warning still surfaces.

## The `validate` and `build` MCP tools report the validation mode

Their `output` carried only `ARXML generated: … (AUTOSAR 4.3.0)`, so an agent could not say
whether the file had been checked against the AUTOSAR schema or structurally. The second line of
`output` is now the CLI's own sentence: `ARXML validated against <schema>.` or
`XSD validation is skipped (requires the licensed <file> schema).` The result shape
(`success`, `errors`, `output`) is unchanged.

## The architect agent profile explains how a collection grows

`swcraft-architect.agent.md` — the repository profile, its bundled copy in the extension, and the
template `swcraft init` scaffolds — gains one paragraph under rule 3: a list of composites grows by
a `create` at `{"field": …}` + `{"member": …}`, a map by `{"field": …}` + `{"key": …}`, and an
`update` that sends the whole collection back is a `schema-violation`. Both slips cost one round
trip each in two consecutive rehearsals; `discover` already publishes the `collection` descriptor
that decides the address, and the profile now says what to do with it. Re-run
*SWCraft: Onboard Project* (or *Repair MCP Config*) in an existing project to pick up the new
profile — the asset is overwritten outright.

## Not in this release

The `discover` field descriptions for `swc.memory` and `tasks.runnables` could say the same thing
in the contract's own words. That is a model-contract change, outside what a release branch may
carry; it is recorded for `main`.
