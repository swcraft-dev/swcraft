# SWCraft 0.3.0

**This is the first release that is tagged.** The three
parts it carries (the model contract, the generic model kernel, the specialized
coverage and legacy removal) rebuilt how the product knows what a model *is*: every layer,
kind, field and rule is now declared once, in a machine-readable contract shipped inside the
`swcraft-tools` wheel, and the reader, the differ, the impact analysis, the scaffolder and
the editing protocol all derive their layer knowledge from it. Nothing about what you write
in YAML, what the CLI accepts, what the MCP server offers, or what ARXML comes out changed
by design — and the byte-identity of the outputs was the oracle the rework was held to.

Upgrade all four artifacts together; the lockstep rule and the exact internal pins are
unchanged from 0.2.0:

```
swcraft-tools==0.3.0
swcraft-mcp==0.3.0
swcraft-agent==0.3.0
```

plus the `swcraft-vscode-0.3.0.vsix` extension. `swcraft init` scaffolds a project whose
`requirements-swcraft.txt` already carries these pins.

The release commit is tagged `v0.3.0`, and the release branch `release/0.3` is cut from
that tag. Fixes found while the showcase demonstrations are rehearsed ship from it as
`0.3.x` patch releases.

## What did not change, and how that is known

- **YAML model.** `schema.py` and `identifier.py` are byte-identical to 0.2.0. No field was
  added, renamed or re-validated; `check-model` reports the same rules against the same
  files.
- **ARXML output.** No `.arxml` golden changed. The one part that touched
  `writer/elements.py` re-ran its capture oracle before release: 35 files
  (10 artifacts at both AUTOSAR 4.2.2 and 4.3.0, plus 22 read-only CLI streams) are
  byte-identical to the baseline taken before the change. Its qualification-impact record is
  kept with the maintainer.
- **CLI.** The same subcommands, flags, exit codes and messages.
- **MCP surface.** Still 13 tools, with byte-identical names and signatures. The
  `discover` payload has the same schema; three field *descriptions* were corrected
  (below).
- **VS Code extension.** No source change; the same seven commands.
- **Environment.** The `SWCRAFT_*` variable set is identical. The contract lives inside the
  wheel — no project file, manifest key or directory is added.

## The model contract is now load-bearing

`tools/src/swcraft_tools/model_contract/model-contract.json` (contract version `1.4.0`)
and its `binding.json` are loaded once per process and read at import time by the reader,
the snapshot and differ, the editing registry and diagnosis, and the agent's scope-proposal
schema. In 0.2.0 the contract was inert package data; now a missing, unparseable or
unsupported-major contract stops `import swcraft_tools.reader` — the CLI and the MCP server
refuse to start rather than run on a guessed model shape. The failure is
`UnsupportedContractVersion` (screened on the raw text before it is parsed) or
`ContractShapeError`. Full JSON-Schema validation of the contract runs only when
`jsonschema` is installed (the `dev` extra); a plain install gets the version and
top-level-shape guarantees.

The contract version is **not** the product version and does not move with it.
`swcraftVersion` inside the contract records the product version it was
transcribed against and is bumped with the product.

A user-visible consequence of deriving rather than listing: `swcraft init` still creates
the same nine directories, but prints them in contract order — `connectors` now precedes
`data_types` in the `Created …` lines.

## Editing-protocol refusals that are new

Path policy moved into the kernel (`model_registry.segment_refusal` / `path_refusal`) and
closed three gaps. An element identity is now refused at bind time when it:

1. contains a **non-printable character** — any control character, tab, newline, `DEL`,
   `U+2028`/`U+2029` — which 0.2.0 accepted into a filename;
2. exceeds **198 UTF-8 bytes** — the 255-byte filesystem limit minus what the commit path
   adds (`.yaml`, the 32-character temp suffix and `.swcraft-commit.tmp`). In 0.2.0 an
   over-long identity passed every validation pass and human review, wrote its commit
   intent, then failed mid-apply with a bare `OSError`;
3. composes an **illegal file name** although it is a legal segment — `A.` → `A..yaml`. In
   0.2.0 the protocol accepted it, the writer refused it, and the audit classifier still
   treated it as an element address.

One rule was loosened: a placement directory (`swc/{group}/`) is allowed the full 255 bytes,
and reads honour that too, so a group directory of 199–255 bytes already on disk does not
turn a readable project into a refused whole-layer read.

An element whose existing `name`/`id` trips one of the three rules is still read and built;
it is refused only when addressed through MCP. Rename it before editing it through the
protocol.

## Review boundary and commit safety

These landed after 0.2.0 was cut and are the behaviour changes a 0.2.0 MCP user is most
likely to meet.

- **`.env` is honoured for the host channels.** `SWCRAFT_REVIEW`, `SWCRAFT_APPROVED_SCOPE`
  and `SWCRAFT_SCOPE_ID` are re-read *after* the project's `.env` is loaded. In 0.2.0 they
  were resolved at module import, so a `.env` that set them was silently ignored — a
  `.env`-configured `elicit` ran fail-closed as `stage-only`, and a `.env`-configured
  scope ran unscoped. Those values now take effect. Corollary: a host that means *unscoped*
  exports both scope keys **empty** rather than leaving them unset.
- **Every delta entry reaches the human.** The review prompt no longer truncates at 50
  entries (a 60-entry change set used to commit 10 addresses the reviewer never saw).
  Values share a 20 000-character budget with a 4 000-character ceiling applied only under
  contention, so an ordinary whole-element `create` renders complete where the old 400
  characters per value elided it. Every client-authored component of the prompt —
  including `before`/`after` payloads — is control-character-escaped and bounded.
- **A failed elicitation is `abandoned`, not a transport error.** A closed stdio stream or an
  uncoercible answer now produces a terminal lifecycle record and a note, instead of a
  `change_set_staged` with no terminal record.
- **In-process commits are serialized per model root.** Two approved change sets in flight
  on the server's worker threads could both pass the same baseline check and both apply.
- **The audit commit block is defined positively.** One classifiable writer entry per
  committed element, plus the lifecycle and the three host records; anything else inside
  the span — for instance a `create_swc` written by `swcraft import` from another process —
  now breaks completeness instead of being ignored. Every audit reader tolerates a
  corrupted or truncated `audit.jsonl`.

## Three `discover` field descriptions are corrected

The schema is unchanged; the prose an agent reads is not.

- `swc.memory`: in a project that declares no resources the analysis returns before reading
  anything, so an unknown pool key is reported by no check.
- `interfaces.data_elements`: the claim that "the current `add_interface` wrapper
  hard-codes exactly one member" — false since 0.2.0 removed that tool — is gone.
- `resources.*.threshold`: a safety act the **server** classifies from the staged
  before/after values, not one the host classifies.

---

## `swcraft diff` and `swcraft impact` list requirements first

Text and JSON output of `diff`, and the output of `impact`, now place the `requirements`
section first. `schema_version` is still `1`; key order is part of the JSON
contract, so a consumer that relied on the first key being another layer needs adjusting.

## Python API: removed names

This matters only to code that imports `swcraft_tools` directly; the CLI and the MCP server
are unaffected.

Thirteen module-level layer tables that restated what the contract now declares were
deleted: `session._LAYER_DIRECTORIES`, `session._RECURSIVE_LAYER_DIRECTORIES`,
`differ._LAYER_DISPLAY`, `differ.COLLECTION_IDENTITY`, `cli._MODEL_SUBDIRS`,
`impact._LAYER_KEY_FNS`, `reader.SWC_PLACEMENT_FIELD`, `reader.UNGROUPED_SWC_PLACEMENT`,
`authorization._LAYER_MODELS`, `authorization.LAYER_NAMES`, `authorization.LAYER_FIELDS`,
`authorization.LAYER_IDENTITY_FIELDS` (and `reader.LAYER_GLOBS`, which existed only between
the two releases). Six projected tables in `editing/registry.py` — `LAYER_SPECS`,
`KIND_NAMES`, `KIND_DESCRIPTIONS`, `FIELD_ANNOTATIONS`, `COLLECTION_SPECS`,
`PLACEMENT_FIELDS` — are private now. The facts they carried are unchanged and are read
from the registry.

`editing/registry.REGISTRY` and `build_registry(...)` survive. Every `registry=REGISTRY`
default argument became `registry=None`, resolved in the body to the contextually current
registry — identical in production, substitutable in-process through
`model_registry.use_registry()`.

New public modules: `swcraft_tools.contract`, `swcraft_tools.model_registry`,
`swcraft_tools.model_state`, `swcraft_tools.relations`.

## Upgrade checklist

1. Install the four artifacts at `0.3.0`.
2. Re-run `SWCraft: Onboard Project` (or `Repair MCP Config`) to pick up the two refreshed
   `.github/` assets: `copilot-instructions.md` now carries a generated layer list that
   marks `resources/` optional and says its absence is what turns the budget rules off;
   `swcraft-architect.agent.md` gains two rules — `intent` never asserts an approval the user
   did not give, and a declined safety answer is final for that change set.
3. If the project's `.env` sets `SWCRAFT_REVIEW`, `SWCRAFT_APPROVED_SCOPE` or
   `SWCRAFT_SCOPE_ID`, those values now take effect — verify they are the ones you mean.
4. Rename any element identity longer than 198 bytes, containing a control character, or
   ending in `.` before editing it through MCP.
5. Adjust any JSON consumer of `swcraft diff --format json` that depended on section order.

Nothing else is required: `swcraft.yaml`, `model/` and `dist/` of a 0.2.0 project load,
validate, build and export byte-identically.
