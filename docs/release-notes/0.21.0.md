# SWCraft 0.21.0

Released 2026-11-03. The release that answers *what state is the architecture in, and where is it
heading*: **`swcraft metrics`**, a report with no overall score, in a terminal, in the panel and for the
assistant. Beside it, the panel review now waits until it is answered, a diagram's port shows what its
interface carries, and the two export tools became one. The MCP server has twelve tools: one export
tool fewer, `architecture_metrics` added. The ARXML SWCraft generates and the model's format are
unchanged from 0.20.0. *What upgrading takes* at the end has, beyond the pin, updating the extension
and the archive together and two client settings for the review tab.

## Breaking: one export tool

**One export tool.** The MCP tool `export_all_components` is gone: call `export_component`
without `swc_name` to export every component (with `output_dir` for a directory of your own).
A call of `export_component` with a component name is unchanged. The ARXML is unchanged.

A client that calls the old name gets the MCP *unknown tool* error. Copilot, Codex and Claude read the
tool list when they start, and no shipped profile names either tool, so the shipped assistants need
nothing.

## Architecture metrics

`swcraft metrics` answers two questions, what state the architecture is in and where it is heading,
from the model alone: nothing is added to the model and nothing is stored. The report opens with an
**Overview**, a short answer to each question in plain words, and **Definitions and method**, then
three blocks:

- **State**: size; how components depend on one another (afferent, efferent and total coupling, hubs
  and isolated components by the mean and two deviations, a top list) and one coupling table per
  composition; cohesion where a component's runnables declare accesses; how much of the model carries
  a safety level, a runnable on a task and a requirement link; and `check-model`'s findings counted by
  class.
- **Movement**: with `--since REV` (repeat it for a series, the first named the base) or
  `--since-head`, the main figures at the revision and now, and the components added and removed.
- **What to look at**: the facts above that name a place, in a fixed order.

Each section says what it measures and, in a sentence computed from the figures, what follows for this
model. Where the model lacks the data a figure needs, the report says `n/a` and why, never `0`, so a
fresh import with no tasks, safety levels or requirements still gets an honest report. There is no
overall score and the report is no gate and no qualification evidence: `swcraft validate` stays the
gate. `metrics` is read-only and exits 0 on a project it can read, unless a revision named with
`--since` cannot be read; `--report` writes `dist/metrics/metrics.md`, and `--format json` prints one
JSON document.

**In VS Code**, *Architecture Metrics* in the panel's *Model* section (and *SWCraft: Architecture
Metrics* in the palette) writes the report and opens it in the Markdown preview. It compares the working
tree with `HEAD`; the new folder setting **`swcraft.metricsSince`**, a list of revisions, names another
base and further points of the series. **For the assistant**, the new MCP tool
`architecture_metrics(since)` answers with the two answers, each section's conclusion and the figures
beside them, every list capped at ten; the CLI's report is the long form. The guide's new page
*Architecture metrics* explains each figure in plain words.

A revision too long for the system's command line is refused as a revision that could not be read,
named by its first 64 characters; it was reported on Windows as a model root not found.

## The panel review waits until it is answered

The panel review now waits until it is answered. There is no ten-minute deadline: the question stays in
the SWCraft review tab until a decision, the client's cancellation of the call or the end of the
assistant's session. The assistant shows progress every minute, and closing the session ends the wait.
The review record's format is now `2`: an old and a new install of the extension and the server refuse
each other's review records, so nobody is asked; update both together. Answers whose question is gone
stay in `$HOME/.swcraft/reviews/` until you empty it.

## Diagrams: what a port carries

Resting the pointer on a port or on a sequence diagram's data message now shows what its interface
carries — the data elements with their types, or the operations with their arguments — up to eight
lines and then how many are left; on a port with more, a click opens the whole list beside the
picture, closed like the overview's connector list. The SVG files carry the same text. Search now also
finds data element, operation, argument and type names.

## For contributors

The runtime pins did not move: `update-pins` rewrote nothing, so Node.js, CPython, `elkjs` and the
companion extensions are 0.20.0's.

## What upgrading takes

1. **Install the 0.21.0 archive, then set `toolchain_version: "0.21.0"`** in each project's
   `swcraft.yaml`. Until you do, every command that writes or gates refuses a project pinned to
   0.20.0 with the pin sentence. The read-only commands (`diff`, `impact`, `list`, `metrics`,
   `query`, `resource-report`) and `swcraft guard` only print a warning, so an assistant keeps
   working meanwhile.

2. **Update the SWCraft extension and the archive together.** The review record's format moved to
   `2`; an extension and a server of different releases refuse each other's questions.

3. **Run *SWCraft: Onboard Project* again.** The assistant profile and the Copilot instructions now
   say that the review waits until it is answered. It overwrites them, so keep a copy of anything
   you edited in them.

4. **If you use Codex**, change `tool_timeout_sec` in its SWCraft stanza from 660 to 86400 (the
   guide's *The assistant* has the stanza). On Codex's first prompt for a SWCraft tool, choose
   **Always allow** or **Allow for this session**.

5. **If you use Claude Code**, add `"env": {"CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS": "0"}` to
   `$HOME/.claude/settings.json` or the project's `.claude/settings.local.json`, so the review's call stays
   in the foreground. It applies to every MCP server of that Claude Code. Copilot needs nothing.

6. **A client or script that called `export_all_components`** calls `export_component` without
   `swc_name`.

Nothing else moves in a project: the model's files, the hooks and the generated ARXML are unchanged
from 0.20.0. A project on 0.19.2 or earlier follows [0.20.0's note](0.20.0.md) first.
