# SWCraft 0.16.2

Released 2026-10-15. A patch release of the 0.16 line: the *references* link in VS Code no longer
counts, and the diagrams draw a port's shape only where the model declares its type, dash the
connections the model check cannot judge, and light any port under the pointer. The commands'
options, the set of MCP tools and their arguments, and the ARXML SWCraft generates are unchanged
from 0.16.1; the model's format is unchanged too, and one field's description is reworded (below).
The archive's sizes are the tag run's, recorded under *The archive*.

## The *references* link shows at once and counts nothing

On a large project the line of links above an element's `name:` line could appear ten seconds or
more after you switched to the file, and until it appeared a click on *impact* or *diagram* did
nothing: the `N references` count asked `swcraft impact` for every file you opened, one file after
another. The link now reads plain `references`, asks nothing until you click it, and the line
appears with the file, saved or not.

A click is **Find All References** on the element, run at that moment. The list therefore includes
the element's own `name:` line again, as Shift+F12's does; 0.16.0's counted link left that line out
so that the list matched its number. There is nothing to save first, and no *save to count* or
*unavailable* title any more.

## A port's shape only for a declared type

**The square is the port; the shape says its type.** The sender-receiver or client-server shape is
drawn beside a port's square only when the model declares that kind: a declared interface, or an
external interface whose kind is `SENDER-RECEIVER-INTERFACE` or `CLIENT-SERVER-INTERFACE`. Every
other port is the **bare square**:

- a port on an external interface of any other kind — mode-switch, `PORT-INTERFACE`,
  `DATA-INTERFACE` and the rest. 0.16.1 drew every one of them as sender-receiver;
- a port whose interface the model does not declare or cannot find;
- a port of an external component. 0.16.1 drew its shape from the `observed_interface` the import
  records there, or drew it as sender-receiver when there was none. That hint is an observation, not
  a declaration, so no diagram draws it any more; the port's text now ends in *(external component,
  interface not declared)*, and `swcraft query` still shows the hint. The field and the import are
  unchanged.

## A dashed line is a connection nobody checked

A connector or a delegation is drawn **dashed** exactly where the model check cannot judge whether
its two ports fit: an end on an external component's port, two different external interfaces, a
declared interface against an external one, or a port that declares no interface against an
external one. The connection may be right or wrong; the file that declares the other side would
tell, and the model does not hold it. Rest the pointer on a dashed line and its text says why, in
the check's own words, on the line under its name.

A solid line is one the check judges. Where it finds that the two ports do not fit — an external
interface of the other kind, or directions that disagree — `swcraft check-model` reports it, and the
line stays solid. An overview's numbered line stays solid even when some of its connectors are
dashed on the internal block diagram, and a sequence diagram's dashed arrows keep their own meaning
(a data flow after a step); they say nothing about whether a connection was checked.

## Hover and selection on the diagram pages

- **Any port lights up under the pointer**, connected or not; a connected one lights its lines and
  the ports at their other ends too. The whole port takes the pointer, its square and its shape
  alike.
- **The text shows at once**, in a small box next to the pointer, for a port, a line, a box, a frame
  and the way up alike, in place of the browser's own tooltip, which came late. It follows the
  pointer whether or not a click has kept something lit, and it goes when the pointer leaves, on a
  press and on *Escape*. The status line under the picture stays. The SVG files opened on their own
  keep the browser's tooltip.
- **What is lit is blue** (`#1a5fb4`, the pages' link colour) where it was black: a port's square
  and its shape are drawn equally thick, a lit line is thicker, and a dashed line stays dashed. A
  search keeps its orange and red.

## The guide's big picture

The guide said requirements are what components and interfaces "point back at". The link points the
other way: a requirement's `links` names the components it is allocated to. The page now says so.

## The model's contract is `10.1.1`

`contractVersion` moves from `10.1.0` to `10.1.1`, a prose-only patch: only the description of
`field:swc.port.observed_interface` changed, to say that the diagrams no longer draw the hint. No
field, kind or rule is added, removed or renamed, and a model file needs no change.

## The archive

The runtime payloads are 0.16.1's, unchanged: Node.js 22.23.2, CPython 3.11.16 (the
python-build-standalone build of 2026-09-01), `elkjs` 0.12.0 inside the `swcraft-tools` package, and
the two extensions of the pack, Red Hat XML 0.29.3 and Red Hat YAML 1.25.0. The archive carries the
same packages as 0.16.1. The Linux archive measures **197 458 709 bytes**
(SHA-256 `abeff2ca…49060ff7`) and the Windows archive **201 520 656 bytes** (`667f7d37…9fc7fe06`),
as the tag run of 2026-10-15 published them: 92 091 and 84 893 bytes more than 0.16.1's.

## What upgrading takes

Install the 0.16.2 archive, then set `toolchain_version: "0.16.2"` in each project's `swcraft.yaml`.
Until you do, every command that writes or gates refuses a project pinned to 0.16.1 with the pin
sentence and never reaches the model. The read-only commands (`diff`, `impact`, `list`, `query`,
`resource-report`) and `swcraft guard` only print a warning, so Copilot keeps working meanwhile.

Nothing else in a project moves: the model, its format, the hook file `.github/hooks/swcraft.json`
and the agent files are the same as 0.16.1's, so *Onboard Project* has nothing to replace and
*Check Editor Tooling* reports them as this release's. Regenerate the diagrams (the panel's
**Diagrams**, or **Build**) to see the new drawing. A 0.15.0 project upgrading straight to 0.16.2
reads [0.16.0's note](0.16.0.md) for what changed there.
