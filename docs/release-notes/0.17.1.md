# SWCraft 0.17.1

Released 2026-10-19. A patch release of the 0.17 line: in VS Code, the Problems panel fills at once
after *Check Model* on a project with thousands of findings, where 0.17.0 took tens of seconds on
macOS and longer on Windows. The commands' options and output, the set of MCP tools and their
arguments, the ARXML SWCraft generates and the model's format are unchanged from 0.17.0. The
archive's sizes are the tag run's, recorded under *The archive*.

## The Problems panel fills at once

*Check Model*, and the `check-model` step of *Build*, place each finding the command reports on the
line of the file it is about. To find that file, 0.17.0 read the list of the folder that holds it
**once per finding**: on a project with thousands of requirements and warnings the requirements
folder was listed once per warning, tens of millions of file names, before the panel showed
anything. A run now lists each folder once, and finds each name in that list at once: the folder
listings fall from one per finding to one per folder, and the element files read are the same.

`swcraft check-model` itself takes the same time as before; the panel now follows it without a
second wait. Windows lists a large folder far more slowly than macOS, so the wait 0.17.0 added there
was the longer one.

Nothing is kept from one run to the next: a requirement file added after one *Check Model* is
found by the next. The hover and the two quick fixes on a trace link read the
model the same way, a folder once per request.

## The archive

The runtime payloads are 0.17.0's, unchanged: Node.js 22.23.2, CPython 3.11.16 (the
python-build-standalone build of 2026-09-01), `elkjs` 0.12.0 inside the `swcraft-tools` package, and
the two extensions of the pack, Red Hat XML 0.29.3 and Red Hat YAML 1.25.0. The archive carries the
same packages as 0.17.0. The Linux archive measures **197 644 320 bytes**
(SHA-256 `46b66e06…c0499ec8`) and the Windows archive **201 706 252 bytes** (`47907054…38080029`),
as the tag run of 2026-10-19 published them: 7 407 and 7 393 bytes more than 0.17.0's.

## What upgrading takes

Install the 0.17.1 archive, then set `toolchain_version: "0.17.1"` in each project's `swcraft.yaml`.
Until you do, every command that writes or gates refuses a project pinned to 0.17.0 with the pin
sentence and never reaches the model. The read-only commands (`diff`, `impact`, `list`, `query`,
`resource-report`) and `swcraft guard` only print a warning, so Copilot keeps working meanwhile.

Nothing else in a project moves: the model, its format, the hook file `.github/hooks/swcraft.json`
and the agent files are the same as 0.17.0's. A 0.16.x project upgrading straight to 0.17.1 follows
[0.17.0's note](0.17.0.md) first: its requirement files and one line of `swcraft.yaml` need an edit.
